# ⚙ Машинариум — команда AI-агентов в 3D-бункере

Ставишь задачу боту в Telegram → над ней работает команда из 4 агентов
(🔵 Менеджер → 🟢 Аналитик → 🔴 Разработчик → 🟣 Ревьюер), а в браузере ты
видишь их как четырёх разных 3D-роботов в стимпанк-бункере: они просыпаются,
крутят механизмы, искрят, передают друг другу «посылки» с результатами.
Живые апдейты идут в Telegram (одно редактируемое сообщение), финальный отчёт
собирается из работы всех четверых.

## Архитектура

```
Telegram ──► bot ──POST /api/task──► orchestrator ──► пайплайн 4 агентов
                │                          │              (OpenRouter API)
                │                          ▼
                └──── Redis Stream (единая шина событий) ──► WebSocket ──► 3D-дашборд
```

- **redis** — Redis Streams, единственный канал связи между сервисами.
- **orchestrator** — FastAPI: приём задачи (`POST /api/task`), пайплайн
  Manager→Analyst→Developer→Reviewer через OpenRouter, публикация событий в
  шину, WebSocket-мост (`/ws`) и раздача 3D-дашборда.
- **bot** — python-telegram-bot, long polling. Ставит задачу и ведёт одно
  живое сообщение с прогрессом (`edit_message_text`), затем шлёт отчёт.

Единая нормализованная схема событий — в [common/events.py](common/events.py).
Её читают и бот, и дашборд; отдельной схемы для фронтенда нет.

Почему так: **FastAPI** — асинхронный, один процесс совмещает HTTP, пайплайн и
WebSocket. **Three.js** — настоящий объём, свет и bloom-свечение дают атмосферу
Machinarium, которой не добиться на плоских карточках. **Redis Streams** —
простой durable-лог событий, к которому независимо подключаются бот и браузер.

## Запуск

Всё уже настроено в `.env` (токен бота + ключ OpenRouter + модели). Одна команда:

```bash
docker compose up --build
```

- Дашборд: **http://localhost:8080**
- В Telegram напиши боту `/start`, затем задачу, например:
  _«Проанализируй конкурентов в нише SaaS-отслеживания, напиши план маркетинга
  на месяц, прототип лендинга и код-ревью этого прототипа»_

## Файловая мастерская агентов (реальные файлы, как у coding-агентов)

Агенты не просто отвечают текстом — они **создают настоящие файлы**:

- каждый агент сохраняет свой результат в папку задачи:
  `00_plan.md`, `01_analysis.md`, файлы Developer (`index.html`, `styles.css`,
  `main.py`…), `03_review.md`;
- Developer выдаёт код в формате `===FILE: имя===`, оркестратор парсит и
  реально пишет файлы (робот при этом анимированно «пишет», событие
  `file_write`);
- файлы появляются у тебя на диске в **`machinarium/workspace/<task_id>/`**
  (папка примонтирована в контейнер);
- сгенерированный лендинг **открывается прямо в браузере**:
  `http://localhost:8080/files/<task_id>/index.html`;
- в Telegram финальный отчёт содержит кликабельные ссылки на все файлы;
- список файлов задачи: `GET /api/files/<task_id>`.

Безопасность (локальный прототип для одного пользователя): имена файлов
санируются (без выхода за пределы папки задачи), произвольный код **не
исполняется автоматически** — файлы создаются и сохраняются, HTML сразу
смотрибелен, запуск скриптов остаётся за тобой.

## Модели (OpenRouter, бесплатные)

Роль → env-переменная (см. `.env`), меняется без правки кода:

| Роль | Модель по умолчанию | Почему |
|------|---------------------|--------|
| 🔵 Manager  | `nvidia/nemotron-3-ultra-550b-a55b:free` | нужна сила: декомпозиция задачи в JSON |
| 🟢 Analyst  | `nvidia/nemotron-3-super-120b-a12b:free` | быстрее, работа со «сырыми» фактами |
| 🔴 Developer| `poolside/laguna-m.1:free` | заточена под код/контент |
| 🟣 Reviewer | `nvidia/nemotron-3-ultra-550b-a55b:free` | нужна сила: критическая проверка |

Платная альтернатива посильнее — `qwen/qwen3-235b-a22b-2507` (впиши в любую
`MODEL_*`). Если модель недоступна/лимит — шаг откатывается на детерминированный
резерв (веб-поиск + выжимка), задача всё равно завершается.

## Как добавить 5-го агента (напр. Marketer) — без правки ядра

1. Добавь блок в [orchestrator/agents.yaml](orchestrator/agents.yaml): имя,
   заголовок, emoji, цвет/акцент, `builder` (можно `manager` как заготовку),
   `model_env`, системный промпт. Дашборд и бот подхватят роль автоматически.
2. Добавь env-переменную модели (`MODEL_MARKETER=...`) в `.env`.
3. Добавь шаг в пайплайн — метод `_run_<имя>` в
   [orchestrator/pipeline.py](orchestrator/pipeline.py) и вызов в `run_task`
   (+ `_handoff` от предыдущего). Все события идут через хелпер `_emit`.
4. (Опционально) уникальный 3D-робот — новый билдер в
   [orchestrator/static/robots.js](orchestrator/static/robots.js) и запись в
   `BUILDERS`; иначе используется билдер по имени `builder` из yaml.

## Среда-IDE на `/` (Three.js) — одно цельное пространство

Главная страница — **IDE в атмосфере Machinarium**: тёмная ржаво-серая
котельная (ink-wash: зерно, виньетка, приглушённая палитра), в которой живут
4 робота-агента в духе Йозефа (округлые бочонки-тела, большие глаза, состаренный
металл). Вокруг — панели IDE:

- **CHAT (справа)** — общайся с командой прямо в браузере, без Telegram:
  пишешь задачу → агенты берут её в работу, сообщения и файлы идут в чат,
  финальный отчёт приходит отдельной плашкой со ссылками на файлы.
- **FILES (слева)** — список файлов, которые агенты создают по текущей задаче;
  клик открывает просмотрщик; для `index.html` есть кнопка «↗ open».
- Роботы **постоянно заняты**: ходят по котельной между постом и рычагом,
  крутят рукоятки, дёргают рычаги; на реальной задаче — работают у пульта,
  искрят на ошибке, передают друг другу «посылки», радуются на успехе.
- Логотип `MACHINARIUM` состаренным шрифтом (Rye), кликабельные механизмы
  котельной (шестерни, ТУРБО, вентили, колба, шкаф), звук-амбиент.

- [static/main.js](orchestrator/static/main.js) — сборка единой сцены: свет+
  bloom, окружение котельной, посты агентов, роботы, «посылки», камера
  (параллакс/зум/наезд на активного), клики (tooltip), WebSocket, демо-режим.
  Модули котельной переиспользуются прямо из `3d/` (importmap на весь документ).
- [static/robots.js](orchestrator/static/robots.js) — 4 разных робота из
  примитивов + машина состояний (idle/thinking/working/tool_call/success/error),
  искры, шкала уровня над головой.
- [static/lib.js](orchestrator/static/lib.js) — процедурные текстуры (ржавый
  металл), плашка имени/уровня/статуса, помощники.
- [static/3d/](orchestrator/static/3d/objects.js) — окружение и механизмы
  котельной (`objects.js`), анимации (`animations.js`), интерактивность
  (`interactions.js`), звук (`sounds.js`), редактор сцены
  (`scene-config.json`). Эти же модули — основа отдельной песочницы `/3d/`.

Полезное:
- **демо без бэкенда**: `http://localhost:8080/?demo=1` — сцена сама проигрывает
  сценарий из 4 агентов по кругу;
- кнопка «звук» — амбиент котельной + щелчки/лязг/пар (Web Audio, без файлов);
- клик по роботу — фокус камеры и tooltip со статусом; клик по механизму
  (шестерня, ТУРБО-рубильник, вентиль, колба, шкаф) — реакция;
- статика примонтирована volume-ом: правки видны по F5 без пересборки образа;
- **/3d/** — та же котельная как самостоятельная песочница механизмов (без роботов).

Новый механизм в котельной = запись в
[3d/scene-config.json](orchestrator/static/3d/scene-config.json) (фабрики — в
`3d/objects.js`, реакции — `ACTIONS` в `main.js`).

## Событийная схема (Redis Stream, плоский JSON)

```
{agent_id, status, timestamp, action, tool_name, tool_status,
 output_preview, full_output, error_message, task_id, chat_id, extra}
```
`status`: task_received · started · thinking · tool_calling · working ·
handoff · completed · error · task_done · task_error.

## Полезные команды

- Лог шины: `docker exec machinarium-redis redis-cli XRANGE machinarium:events - + COUNT 30`
- Задача без Telegram: `curl -X POST localhost:8080/api/task -H 'content-type: application/json' -d '{"prompt":"тест"}'`
- Список ролей: `curl localhost:8080/api/agents`
- Уровни агентов (переживают перезапуск): `docker exec machinarium-redis redis-cli HGETALL machinarium:levels`
